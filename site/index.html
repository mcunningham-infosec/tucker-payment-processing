    Meet the team

    Tucker Payment Processing is a pretend payment company with real AI: Tucker, an AI customer-support agent who also helps you shop at Tucker's Treats, and the AI SOC Squirrel, a bounded AI security analyst that investigates live attacks in Cipher's Lair. On this page, ask Tucker about company policies, or verify as a demo customer and ask about that account, while the Behind the Scenes panel shows exactly what happens to every message.

    The company is pretend. The technology is not.

    • Google Gemini powers Tucker and the AI SOC Squirrel, on the paid tier, so chats are not used to train the model.
    • Google Cloud hosts a hardened Ubuntu Linux server running Apache, Python (FastAPI) and PostgreSQL.
    • Live attack testing: Cipher runs 50 real attacks (the OWASP Top 10 for web apps and for AI) against this site from inside its own server. Code-run detection rules wake the AI analyst and block the attacker.
    • Monitoring and alerts: Google Cloud Monitoring emails the owner when a defense fails, a spending threshold is crossed or someone hits a lockout.
    • Cloudflare sits in front of the site: DDoS protection, a web application firewall and bot defense. The server only accepts web traffic that comes through Cloudflare.
    • HTTPS everywhere with an automatically renewing certificate and strict security headers.
    • Zero-trust admin access: no admin port open to the internet; administrators get in only through Google's identity-checked tunnel with two-factor authentication.
    • Least privilege: the server's only cloud permission is writing its own alerts to Google's logging; Tucker's chat can only read the database; the store can add an order only through one function that re-prices everything itself; nobody can edit or delete an order; and there is no database password to steal.
    • Open source: every line is on GitHub, including Cipher's attacks, the defenses and the AI SOC. Security that only works while the code is secret isn't security.

    Tucker's rules (our AI policy)

    • Read-only. Tucker can look things up, including your Tucker's Treats orders, but can't change anything: no refunds, no moving money, no unfreezing cards, no editing orders.
    • The code decides access, not the AI. Tucker can only see the customer you verified as, and only for this session.
    • Last 4 digits only. Full card numbers never exist in the system, and an output filter masks anything that looks like one anyway.
    • Prompt-injection shield. Attempts to rewrite Tucker's rules are blocked before they reach the AI.
    • On topic. Tucker only talks about Tucker Payment Processing.
    • Spending cap. AI costs are capped three ways. If the cap is reached, Tucker takes a nap instead of failing.
    • Grounded answers. Policy answers come from the company's own policy documents, and Tucker names the source.

      A readiness review against the criteria a SOC 2 auditor tests.

    Privacy

    No tracking or advertising cookies, so there's no cookie banner. Our only cookie is a session cookie that keeps your chat together and expires when you close the browser; Cloudflare, which protects the site from attacks, may add a short-lived security cookie to tell people from bots. The only outside script is Cloudflare's "are you human?" check on Cipher's Lair. The web server keeps a standard visit log (IP address, rough location, pages viewed) for at most two days for the owner's daily security summary, then deletes it. Chats aren't stored with your IP address. Please don't type real personal or card information.

    Built in the open

    The code, database design, guardrail tests and server configuration are all public: view the code on GitHub. Security that depends on secret code isn't security; the protections here hold even when you can read every line.

# Two database logins, one Linux user, no passwords

The app runs as the Linux user `tucker_app` and connects to PostgreSQL over the local Unix socket only.
PostgreSQL's *peer* authentication checks the Linux user, so there are no database passwords to steal.

The chat uses the database login `tucker_app` (read-only on the demo data).
The store's checkout uses the login `tucker_store` (may only call `demo.place_order()`).
To let the same Linux user log in as `tucker_store`, PostgreSQL needs a user-name map:

`/etc/postgresql/16/main/pg_ident.conf`
```
tuckermap   tucker_app   tucker_store
```

`/etc/postgresql/16/main/pg_hba.conf` (above the general `local all all peer` line)
```
local   tucker   tucker_store   peer map=tuckermap
```

Then `sudo systemctl reload postgresql`.

Install order for the database: `schema.sql`, `roles.sql`, `seed.sql` (generated by `make_seed.py`).
